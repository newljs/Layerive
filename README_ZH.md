# Layerive

**一个按项目管理图片、对话和修改历史的本地创作工作台。**

Layerive 用来处理需要反复修改的图片工作。你可以从提示词或已有图片开始，继续改图、改字、局部替换、扩图和提取素材；每次结果都保存为项目中的一个版本，相关图片、对话和模型配置留在本机。

## 它解决什么问题

普通的提示词出图页更擅长“生成一张新图”。如果只是想换掉图片中的一句文字、修改某个局部、替换一个主体或向外扩展画面，往往还要对着模型反复调整提示词，结果也不一定只改变指定位置。

Layerive 把这些常见操作做成了工作台中的直接工具：识别并修改图片文字，框选区域后输入要求或上传参考图，选择目标比例扩图，以及提取素材、提升清晰度和去水印。图片变清晰、去水印等操作可以直接点击对应工具发起；改字和局部修改则围绕识别结果或选区完成。视觉模型负责理解图片和选区，图片模型负责执行修改。用户不需要先研究怎样组织一大段编辑提示词，也不必为了一个局部变化反复重新生成整张图。

这些操作都保存在同一个项目中。每次生成或修改会形成一个版本，可以回到任意结果继续处理、比较前后差异，或从旧版本建立新的分支。项目不绑定云端平台或固定模型服务；除了调用模型时会向你配置的服务发送请求，图片、对话和版本数据都保存在本机。

## 功能

### 项目与素材管理

- 项目库提供卡片和列表视图，并支持搜索、收藏、复制、重命名和软删除。
- 每个项目分别保存描述、封面、当前图片、默认模型和未提交的工作台内容。
- 项目可以单独导入或导出为 ZIP，也可以备份和恢复全部本地数据。

### 图片创作与编辑

- **文生图**：一次生成 1–4 张图片。多张结果属于同一个版本，可以选择其中任意一张继续编辑。只支持单张返回的服务会被拆成多次请求，因此可能产生多次计费；平台限流时会自动退避重试。选择多张时无需额外开关：视觉模型会根据提示词自动判断是生成同一内容的多个候选，还是把“喜怒哀乐、不同方案、分别生成”等明确意图拆成每张不同的子提示词。
- **图生图和提示词改图**：以上传图片、粘贴图片或历史版本为输入，通过文字说明继续修改。上传后会选择当前模型最接近原图比例的输出尺寸；日日新 U1.5 Lite 会在请求时自动生成符合平台尺寸规则的临时副本，不改写本地原图。
- **变量批量处理**：点击画布右上角的“批量处理”按钮，以画布当前展示的图片为统一参考图，在同一个提示词编辑区的任意光标位置点击“插入变量”；变量会作为不可编辑标签留在文字流中，支持插入多个变量，也可点击标签内的 × 整体移除。设置 2–50 张后，下方按“每张图片一行、每个变量一列”生成输入框。例如模板“生成一致的［头部］人身怪物，穿［服装］”可逐行填写“狗头 + 红色夹克、驴头 + 蓝色夹克……”，每张同时替换这一行的全部变量，并尽量保持其他区域一致。也可以切换到“提示词列表”标签页，导入每行一条提示词的 TXT 文件或直接粘贴多行文本：导入后自动回显到文本框中，识别到多少行就生成多少张（2–50 条，单条上限 1000 字符），每行直接作为该张的完整提示词，不再叠加变量约束。每完成一张就立即显示在画布下方，并持续更新剩余数量和预估时间；单张失败不影响后续词条，也可随时取消并保留已完成结果。每一行 / 每个词条都会独立调用一次图片模型，可能按张计费。
- **图片变清晰**：调用改图模型补充清晰度和细节，并要求模型尽量保持原有主体、文字、构图和风格。
- **局部修改**：可从图片内外起拖框选区域，并拖出画布边缘。圈选后输入修改意见，或在浮窗上传 / Ctrl+V 粘贴参考图（PNG/JPEG/WebP，最大 10MB）。例如框选人头并上传狗的照片，视觉模型会推断换头意图、定位两图中的主体，后台裁剪狗头并拼贴到目标位置，再交给图片模型自然融合。上传参考图后文字可留空，也可补充具体要求。参考图模式会保留框外原图像素，以原图尺寸保存 PNG；请为颈部等连接处留出选区空间，融合质量取决于模型能力。任务显示定位、合成、生成和保存进度，可随时取消；原有纯文字局部修改仍可使用。
- **提取素材**：可从图片内外起拖框选想提取的内容（例如电影银幕），越过图片或中间画布边缘仍可完成选择；系统取与原图相交的区域自动截图，由视觉识别模型聚焦主体、剔除圈入的边缘干扰（如两侧座椅），再由改图模型生成一张只包含该主体、内容与原图一致的独立素材图；可选填写补充说明帮助识别意图。
- **扩图**：选择当前模型支持的目标尺寸 / 比例，在画布中预览扩图边界后确认；系统以当前图片为中心组织扩图提示词并发起编辑。
- **去水印**：视觉模型先判断并定位水印，确认后再由图片模型修复对应区域。
- **图片改字**：识别模型将图片可见文字按区域拆分为可编辑输入框；支持替换或清空删除文字，也可手动框选区域新增内容。提交后按原图比例匹配当前图片模型支持的输出尺寸；点击“提交并改图”后弹窗会立即关闭并回到项目对话，从视觉规划阶段开始等待生成。提交失败时会自动恢复编辑弹窗和原内容。
- **识别结果复用**：同一图片首次完成文字识别后会保存在本机；再次编辑文字时会直接复用结果。切换视觉识别模型，或修改该模型的接口/模型名后，系统会自动重新识别。
- **项目风格提示词**：为项目设定统一的文生图风格；改图操作保留原图语境。
- **提示词画廊**：浏览内置模板，或维护自己的提示词和配图。视觉模型可以从上传图片提取提示词；工作台中的图片也可以通过右键菜单加入画廊。

### 版本、对话与对比

- 每次生成、编辑、变量批量处理、图片变清晰、局部修改或扩图都会产生新的版本；上传图片也会作为可追溯的起始节点。变量批量处理的结果会逐张追加到同一个版本。项目已有图片后仍可继续上传新的图片，并以其为输入进行后续编辑。
- 可查看完整版本树，支持缩放、空白处拖拽平移、点击节点跳转画布，并从任意节点继续形成分支。历史列表会用缩略图拼图和数量标签标出多图版本，可将该版本全部候选图一键下载为 ZIP。
- 工作台会保留每轮提示词、所用模型、版本号和生成结果；可以复用提示词，或选择某张结果继续。
- 支持并排对比和滑块前后对比，也可从历史图片中选择对比对象。

### 模型接入

图片生成模型可单独新增、编辑、测试、删除并设为默认；每个项目也会记住创建时的默认模型。支持的图片提供商：

编辑工作台顶部可分别选择“出图模型”和“视觉识别模型”。视觉模型选择会按项目自动保存，并用于图片文字识别与改字、局部修改、去水印、提取素材和提示词提炼；切换模型后，文字识别缓存也会按所选模型分别复用或重新识别。

| 提供商 | 接入方式 | 适用能力 |
| --- | --- | --- |
| 日日新 SenseNova | 专用请求适配 | 文生图、图生图、提示词改图；生成请求默认关闭官方水印，编辑输入自动规范化并使用自动输出尺寸 |
| OpenAI 兼容 | Images API / 兼容中转接口 | 文生图、图生图、提示词改图，具体能力取决于服务端模型 |
| Gemini | Gemini 原生图片接口 | Gemini Nano Banana 等图片生成模型 |
| Grok | xAI 原生图片接口 | Grok Imagine 图片生成模型 |

- 可配置独立的**视觉识别模型**，用于图片改字和局部修改的图片分析与提示词规划。
- 视觉识别支持 Anthropic Messages、Chat Completions 和 Responses 三种 API 格式；旧日日新与 `dots3-note` 等配置保持兼容。
- 使用 SenseNova Token Plan 的 `sensenova-6.8-flash-lite` 时，选择 Chat Completions，并填写 `https://token.sensenova.cn/v1`；应用会调用标准 `/chat/completions` 路径。
- 每个模型可声明文生图、图生图、提示词改图或图片理解能力。工作台只展示并调用当前选中模型支持的操作和尺寸。
- 内置演示模型，不填 API Key 也可以体验项目、对话和版本流程。

## 快速开始

### 环境要求

- Node.js **22.13+**
- npm **10+**

### 本地开发

```bash
npm install
npm run dev
```

开发模式会启动前端和本地 API 服务。浏览器访问 [http://127.0.0.1:5173](http://127.0.0.1:5173)，本地 API 默认使用 `8788` 端口。

### 构建与运行

```bash
npm run build  # 类型检查并构建到 dist/
npm start      # 启动本地服务，同时托管前端与 API
```

> [!TIP]
> 日常本地使用时，先执行一次 `npm run build`，之后运行 `npm start` 即可；开发或修改代码时使用 `npm run dev`。

### 桌面版

同一份源码可以构建为 Electron 桌面应用：

```bash
npm run desktop:dev   # 构建后以 Electron 启动
npm run desktop:dist  # 生成安装包与便携版
```

桌面版会在系统的 Layerive 用户数据目录保存 SQLite 数据库、项目图片、画廊和模型配置；程序升级不会覆盖这些数据。浏览器本地版与桌面版使用相同功能代码，但默认各自保存本地数据；可通过完整备份 / 恢复迁移项目。

也可以直接从 [GitHub Releases](https://github.com/newljs/Layerive/releases) 下载预构建安装包：推送 `v*` tag 后 GitHub Actions 会自动发布 Windows（安装包 + 便携版）、macOS（x64 + arm64 DMG）和 Linux（AppImage + deb）产物。

## 配置真实模型

从首页或工作台进入「模型配置」：

1. 选择「添加图片模型」或「添加视觉识别模型」。
2. 图片模型选择 **日日新 / OpenAI / Gemini / Grok**；视觉识别模型选择 **Anthropic Messages / Chat Completions / Responses** API 格式，新建时默认 Chat Completions。
3. 填写显示名称、Base URL、API Key、模型名和能力；API Key 右侧按钮可切换显示与隐藏，也能按需回显已保存的密钥。图片提供商切换后会带入相应的默认接口地址与模型示例。
4. 点击「测试连接」，成功后保存；图片模型可「设为默认」，视觉识别模型可「设为识别默认」。

| 模型类型 | 支持的提供商 | 主要用途 |
| --- | --- | --- |
| 图片模型 | 日日新、OpenAI 兼容、Gemini、Grok | 文生图、图生图、改图、扩图等 |
| 视觉识别模型 | Anthropic Messages、Chat Completions、Responses | 图片改字、局部修改与素材提取的识别和提示词规划 |

### 配置提示

- OpenAI 兼容中转站的参数范围由中转站决定。例如 `quality` 仅接受 `auto`、`low`、`medium`、`high` 时，请在模型默认参数中使用其允许值。
- 图片改字、局部修改、扩图、图片变清晰和素材提取均需要图片模型具有**提示词改图**能力；前两类识别型操作还需要已启用的视觉识别模型。
- 扩图的目标尺寸会受当前图片模型的尺寸限制约束，确认前请以画布预览的边界为准。
- 生成质量、文字准确度和局部保真度受具体模型能力影响；复杂排版建议先做图片改字识别，再配合手动框选逐段处理。

## 本地数据与隐私

- 不需要注册或登录；浏览器本地版的项目元数据存于 `data/app.db`，项目图片保存在 `data/` 下的本地目录。桌面版将同类数据保存在系统的 Layerive 用户数据目录。
- 浏览器本地版的模型配置保存在 `config/models.json`；桌面版保存在其用户数据目录。其中可能包含 API Key。请勿提交到公共仓库，也请谨慎处理备份文件。
- 完整备份会包含项目数据与配置；导入前建议先保留一份现有备份。
- 本地 API 仅监听 `127.0.0.1`，不会直接暴露给局域网或互联网。

## 常见问题

### 页面能打开，但无法生成图片？

演示模型只用于体验工作流。请在「模型配置」中添加真实图片模型，填写 API Key 并测试连接，然后将它设为默认模型。

### 为什么“图片改字”或“局部修改”不可用？

除了可改图的图片模型外，这些操作还需要视觉识别模型分析图片。请分别配置并启用两种模型，再确认图片模型声明了「提示词改图」能力。

### 怎样迁移数据或换电脑？

在首页导出完整备份 ZIP；在新环境安装并启动 Layerive 后，用恢复功能导入。恢复会覆盖当前本地数据，请先导出一份当前备份。

### 端口被占用怎么办？

开发模式默认使用前端 `5173` 与 API `8788` 端口。停止占用端口的进程；如需改 API 端口，可在启动前设置环境变量 `PIXELFLOW_API_PORT`，并同步修改 Vite 的 API 代理地址。

## 技术栈

| 层 | 技术 |
| --- | --- |
| 前端 | React 19 · TypeScript · Vite |
| 服务端 | Node.js 原生 HTTP 服务 |
| 数据库 | SQLite（`node:sqlite`） |
| 图片存储 | 本地文件系统，按项目归档 |
| AI 接入 | SenseNova · OpenAI 兼容 · Gemini · Grok · 视觉识别模型 |

目录速览：

```text
app/
├── src/            # 首页、工作台、模型配置与前端交互
├── server/         # API、任务调度、模型调用、数据读写
├── public/         # 图标、PWA 资源与提示词画廊素材
├── config/         # 本地模型配置（运行时生成，含敏感信息）
└── data/           # SQLite 数据库与项目图片（运行时生成）
```
