# 2026-10-04 代码与功能检查

本次以三阶段插件改造为重点，检查了注册/宿主/声明校验、原九项功能入口、模型适配衔接、任务取消与输出事务、前端状态、项目复制/导入、桌面资源规则。结合全量服务端回归与隔离浏览器验证，发现并修复以下问题。

| 问题 | 影响 | 修复与证据 |
| --- | --- | --- |
| 终态项目刷新失败后轮询已停止 | 服务端成功但页面停留在旧结果，需要手动刷新 | 项目数据获取成功后才结束轮询；阻止重叠请求并丢弃旧轮询响应。浏览器代理在首次终态刷新返回 503，随后页面自动展示 V2 |
| 通用插件弹窗未隔离粘贴及焦点 | 图片粘贴触发工作台上传、替换主图并使表单消失；Tab 可进入背后的控件 | 弹窗阻止粘贴事件传播，打开/提交/上传时接管焦点、Tab 循环、关闭恢复焦点；保留文本粘贴 |
| 父版本 ID 缺少项目与删除状态校验 | 构造请求可形成跨项目版本树关系，错误 ID 会在生成后才失败 | 普通、插件及三类批量入口统一同步校验；集成测试断言拒绝后不创建任务、不调用模型 |
| recipes 根目录缺失/不可读直接抛错 | 可选插件资源异常使整个应用无法启动 | 将目录错误加入公开 errors，仍注册原有代码插件；缺目录回归通过 |
| 非透明配方允许透明/空透明输出，视觉 null 返回 TypeError | 上色可能保存空白结果，错误提示不稳定 | 非透明配方拒绝 Alpha <250 的像素；null/非对象规划返回 plugin.invalidPlan；反例测试先复现再通过 |
| Windows 导入目录移动出现 EPERM | 合法项目导入偶发失败；本机测试连续复现两次 | 文件移动在事务外对 Windows 占用错误有限重试，不改变 ZIP 路径校验或回滚规则；复制/导入回归恢复通过 |

本地模型测试曾在并行运行时超过原 4.5 秒启动等待，单独运行通过；改为有退出检测的 15 秒启动期限，仍受用例总超时限制。

验证结果：`npm test` 37 项通过；`npm run lint`、`npm run build`、`git diff --check` 通过。服务端测试覆盖三种视觉协议、四种图像协议、原专项操作、新旧入口、透明校验、取消/拒绝、批量部分成功、复制/导入、备份恢复与本机访问限制。构建保留既有单 JS 包超过 500 KB 的提示。

浏览器使用独立数据库、生成的测试图片和本机模拟模型，未触碰真实项目或模型额度；终态刷新故障由本机代理主动注入。未验证真实模型的生成质量，未重新制作或实测三端 Electron 安装包。现有回归通过不代表全部输入组合均无缺陷。
